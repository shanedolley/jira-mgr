# 2026-10-10 UX Review

The desktop app has 30 findings after merging the three lenses: 5 High, 16 Medium and 9 Low. The app ran only over the fake backend (`e2e/desktop/harness.ts`, `JM_E2E_BULK=300`, a scratch `JM_STATE_DIR`), so no live PSAPAC call was made. Screenshots are 1440x900 CSS pixels unless a name says otherwise; the base file is dark, and the `-light` twin is light. Linear comparisons name a file in [docs/design/linear](../design/linear/README.md) or a token in its README.

## Summary

| Severity | Count | UX IDs |
|---|---|---|
| High | 5 | UX1 to UX5 |
| Medium | 16 | UX6 to UX21 |
| Low | 9 | UX22 to UX30 |

The five changes that matter most:

1. **Fix placeholder and field-border contrast (UX1, UX3).** Placeholders measure 3.1:1 to 3.2:1 in light, and field borders 1.2:1 to 1.3:1. Two CSS tokens fix both.
2. **Give the filter field a keyboard route (UX2).** `/` focuses the field and Enter or Down moves to the first match. A keyboard-first app now stops at its own search.
3. **Report failures where the user looks (UX4).** A refused edit prints raw API text under the properties list. Send it through one compact toast that pauses on hover.
4. **Make the layout survive zoom and narrow windows (UX5).** At 200% zoom the Peek buttons and half of every property value fall off the window.
5. **Separate In Progress from Done and selected from focused (UX6, UX12).** Both pairs differ today by hue or by a 1.2:1 fill alone.

## Findings

Each finding lists the lens IDs it absorbs. The lenses are Visual (V), Interaction (I) and Accessibility (A). Source paths sit under `apps/desktop/src/renderer/src/`. Where the interaction lens had no named Linear screenshot, the comparison cites Linear's general behaviour. Sizes: S under a day, M one to three days, L more.

### UX1 Placeholder Contrast

- **Sources:** A2
- **Severity:** High. **Size:** S.
- **Screen:** Login, Create dialog (Original estimate), Peek and page Original estimate, Link form, Worklog fields.
- **Screenshots:** [01-login-empty-light.png](2026-10-10-ux-review/01-login-empty-light.png), [49-create-dialog-prefilled-light.png](2026-10-10-ux-review/49-create-dialog-prefilled-light.png)
- **Evidence:** `LoginScreen.tsx:30` (`placeholder:text-muted/70`); no placeholder class at `CreateIssueDialog.tsx:451`, `IssueProperties.tsx:50` and `:443`, `LinksSection.tsx:95`, so they inherit Tailwind preflight (ink at 50%).
- **Problem:** Two placeholder styles coexist and both fail 4.5:1 in light. The login one also fails in dark. Measured over the real background: login 3.13 light and 3.95 dark; Original estimate 3.22 light and 4.62 dark. Palette, Filter and Summary placeholders use `--muted` and pass at 5.75 to 7.06.
- **Why it matters:** Placeholders are the only hint of the expected format (site URL shape, "2h 30m").
- **WCAG 2.2:** 1.4.3 Contrast (Minimum), 4.5:1 needed.
- **Recommendation:** Add one global rule in `styles.css`: `::placeholder { color: var(--muted); opacity: 1; }`. Remove `/70` from `LoginScreen.tsx:30`. Result: 5.76 light and 7.03 dark on canvas, 5.92 and 6.70 on panel.
- **Linear comparison:** README "tertiary lch(61.8 1.2 272)" on near-black is about 5.5:1. Linear's placeholder is the tertiary token, not a faded one.

### UX2 Filter Keyboard Route

- **Sources:** I4
- **Severity:** High. **Size:** S.
- **Screen:** Tree filter field.
- **Screenshots:** [14-filter-text.png](2026-10-10-ux-review/14-filter-text.png)
- **Evidence:** `keymap.ts:62-69` owns only `c t s a l p e`. Probe: Enter in the field does nothing, Tab goes to the chip's Clear button, `/`, Cmd+F and `?` do nothing, and the first Esc clears the text.
- **Problem:** A user who types a filter must use the mouse to act on a result, or press Esc and lose the filter. No key focuses the field.
- **Why it matters:** The app is keyboard-first (J/K, C, T) and breaks at its main search.
- **Recommendation:** `/` focuses the filter. Enter or Down in the field moves focus to the first matching row and keeps the text.
- **Options:** A) Enter or Down to the list, Esc keeps clearing (cheap, no documented key changes). B) Also make Esc blur first and clear second (closer to Linear, changes a documented key). Recommend A plus `/`.
- **Linear comparison:** Linear moves focus from the filter to the list with Down or Enter (general behaviour).

### UX3 Fields and Properties

- **Sources:** A1, V10, V11, I6
- **Severity:** High (from A1). **Size:** M.
- **Screen:** Login, Create dialog, Tree filter field, worklog and link forms (borders). Peek and issue page properties (rhythm, affordance, placeholders).
- **Screenshots:** [01-login-empty-light.png](2026-10-10-ux-review/01-login-empty-light.png), [49-create-dialog-prefilled-light.png](2026-10-10-ux-review/49-create-dialog-prefilled-light.png), [14-filter-text.png](2026-10-10-ux-review/14-filter-text.png), [22-peek.png](2026-10-10-ux-review/22-peek.png), [24-page-top.png](2026-10-10-ux-review/24-page-top.png), [41-field-start-date.png](2026-10-10-ux-review/41-field-start-date.png), [43-field-original-estimate.png](2026-10-10-ux-review/43-field-original-estimate.png), [59-undo-after-page-edit.png](2026-10-10-ux-review/59-undo-after-page-edit.png)
- **Evidence:** `LoginScreen.tsx:30`, `CreateIssueDialog.tsx:299` and `:451`, `TreeToolbar.tsx:209`, `IssueProperties.tsx:50` (transparent border), `:129`, `:458-460`, `IssueDetail.tsx:21` (`py-1`), `Picker.tsx:234` (`h-7`), `styles.css:12` (`--line`).
- **Problem:**
  1. The only boundary of a text field is a 1px `--line` border at 1.2:1 to 1.35:1 (login 1.32 light and 1.23 dark; Create Summary 1.29 and 1.30; Original estimate 1.32 and 1.23).
  2. Editable property values are plain text until hover, so "None" and "Backlog" read as labels.
  3. Peek rows alternate 36px and 28px (centres at y=142, 174, 206, 242, 278, 309, 337, 365, approximate), because `py-1` plus `h-7` gives 36 for controls and 27.5 for plain text.
  4. Placeholders sit in the value slot ("Estimate 2h 30m"), an empty "Time left (h)" row shows, and Start and Due date are native `dd/mm/yyyy` widgets with a calendar glyph at x=1410.
- **Why it matters:** Low-vision users cannot find where to click or type, and first-time users never learn that a value opens a picker.
- **WCAG 2.2:** 1.4.11 Non-text Contrast, 3:1 needed, measured 1.2:1 to 1.35:1.
- **Recommendation:**
  1. Add a `--field-border` token: light `oklch(0.64 0.012 275)` (3.32 on panel, 3.22 on canvas), dark `oklch(0.52 0.012 275)` (3.25 on panel, 3.41 on canvas). Use it on every input, textarea and bordered picker button; keep `--line` for dividers. Text-entry property fields (Start date, Due date, Original estimate, Remaining) show a 1px `--field-border` at rest.
  2. Every property row is `h-8` (32px) with no `py-1`. Label 13px muted, value 13px/500 ink. Editable rows get a 16px icon, a 12px `--muted` chevron-down always visible, and a hover pill. Read-only rows (Type, Customer, Engagement, Updated) get none. Empty values ("None") render in `--muted`. Add a 1px rule under the title block, and put the editable group first with an 8px gap.
  3. Placeholders become actions ("Set estimate", "Set start date") with a 16px icon. Hide "Time left (h)" until an estimate exists. Style the date input (`color-scheme`, calendar indicator opacity 0.6) and show formatted text when blurred.
- **Options:** For the border, A) one new token for fields (recommended, S). B) Raise `--line` to 3:1, which makes every divider and card edge heavy and loses the Linear look.
- **Linear comparison:** `32-closeup-properties-sidebar.png` and `11-issue-page.png` ("Set estimate", "Add label"); `22-create-issue-dialog.png`; README "Panel border lch(9.8 1.5 272); stronger border lch(14.2 1.5 272)". Linear uses the stronger border on inputs, and jira-mgr's `--line` maps to the weak one.

### UX4 Toasts and Failures

- **Sources:** V14, I10, A7, I1
- **Severity:** High (from I1). **Size:** M.
- **Screen:** Every toast, and a refused property edit on the Peek and the page.
- **Screenshots:** [60-edit-refused.png](2026-10-10-ux-review/60-edit-refused.png), [60-edit-refused-light.png](2026-10-10-ux-review/60-edit-refused-light.png), [55-edit-pending.png](2026-10-10-ux-review/55-edit-pending.png), [57-undo-pending.png](2026-10-10-ux-review/57-undo-pending.png), [59-undo-after-page-edit.png](2026-10-10-ux-review/59-undo-after-page-edit.png), [61-toast-created.png](2026-10-10-ux-review/61-toast-created.png), [53-timer-running.png](2026-10-10-ux-review/53-timer-running.png), [58-undo-done.png](2026-10-10-ux-review/58-undo-done.png)
- **Evidence:** `Toast.tsx:6` and `:22-28` (10s timer, never paused), `:30-34` (`role="status"` container mounts already filled), `:33` (`fixed bottom-4 left-1/2 w-[min(28rem..)]`), `:43-70`; `IssueProperties.tsx:488-492` (inline `role="alert"` after the last group); `IssueDetail.tsx:93-108`; `Shell.tsx:160` (single notice state), `:360-401`, `:545-550`, `:717-722`.
- **Problem:**
  1. A refused edit prints a paragraph below the whole properties list ("Jira answered 400 to PUT /rest/api/3/issue/PSAPAC-4: summary: ... Fix the input and try again."). It exposes a URL and names `summary` for a priority edit, and on the page it can sit off screen. The value flips back with no visible reason, beside a stale "Undid ..." toast.
  2. The toast is a 446px card centred on the window, covers three rows, and gives one line a 76px card with an orphan Dismiss line. Success, undo and warning differ only by a red title.
  3. A new notice replaces the old one, so the first edit's Undo vanishes when a second lands (Cmd+Z still works). Each toast carries up to three bordered buttons.
  4. The 10s timer never pauses on hover or focus. After an edit, focus stays on the Tree, so Undo and Dismiss sit at the end of the tab order. The created-issue Open has no keyboard route.
- **Why it matters:** A silent rollback is easy to miss, the visible Undo can disappear, and a keyboard user cannot reach Open in 10 seconds.
- **WCAG 2.2:** 2.2.1 Timing Adjustable, 2.1.1 Keyboard, 4.1.3 Status Messages.
- **Recommendation:**
  1. Send property refusals through the same toast (`warned: true`, stays until dismissed, sticky `role="alert"`). Copy: "Priority not changed. Jira refused it: <reason>." Keep method and path out of user copy. Flash the reverted row (background `--hover`, 1s).
  2. Single 40px row, auto width up to 28rem: 16px icon (check, undo, warning in `--danger`), 13px message, ghost action, 24px "x". Anchor at `left: 248px; bottom: 16px`, over the Tree pane. Borderless 12px text buttons. Keep the last two toasts stacked.
  3. Pause the dismiss timer on `mouseenter` and `focusin`, restart 5s after leave. Mount one empty `role="status"` region in `Shell.tsx` beside the sr-only ones at `:717-722`, write the title into it, and keep the buttons outside it. Drop the created-issue Open, since Enter on the new row already opens the page.
- **Linear comparison:** README lists no toasts, so Linear is a gap here. `28-issue-peek.png` gives the radius and shadow. Linear reports failed edits as a toast, compact and bottom-left (general behaviour).

### UX5 Narrow and Zoomed Layout

- **Sources:** V19, A3
- **Severity:** High (from A3). **Size:** L.
- **Screen:** Tree with Peek, and issue page, at 1024px, 800px and 200% zoom.
- **Screenshots:** [62-narrow-1024-tree.png](2026-10-10-ux-review/62-narrow-1024-tree.png), [63-narrow-1024-peek.png](2026-10-10-ux-review/63-narrow-1024-peek.png), [64-narrow-1024-page.png](2026-10-10-ux-review/64-narrow-1024-page.png), [66-narrow-800-peek.png](2026-10-10-ux-review/66-narrow-800-peek.png)
- **Evidence:** `Shell.tsx:634` (`grid-cols-[14.5rem_minmax(20rem,1fr)_minmax(21rem,26rem)]`, 888px minimum), `IssuePage.tsx:241`, `apps/desktop/src/main/app.ts:76` (`minWidth 900` guards window size, not zoom). The 720px captures (`r720-peek.png`, `r720-page.png`) were scratch files and are not kept.
- **Problem:** At 1024 the Peek takes 41%: the Tree is 376px, titles truncate ("Customer onboardi...") and the toolbar wraps to three rows (about 130px). Below about 890 CSS px (a 1440px window at 200% is 720) the Peek's Open, Delete and Close buttons and the right half of every property value sit 168px past the window with no scrollbar, and the keyboard can focus them there. At 480px the nav sits at x=-72. The sidebar keeps its full 232px.
- **Why it matters:** A low-vision user who zooms loses Status, Assignee and Priority.
- **WCAG 2.2:** 1.4.4 Resize Text, 1.4.10 Reflow, 2.4.11 Focus Not Obscured.
- **Recommendation:** Under 960 CSS px, collapse the sidebar to a 48px icon rail and show the Peek and page Properties as a right-edge drawer over the list (`min(21rem, 100% - 3rem)`, 360px card, right 8px, 12px radius, shadow `0 4px 40px`, with a scrim). On the issue page, stack Properties under the content below 760px. Give the main grid `overflow-x: auto` as a floor. Under 700px Tree width, merge Filter and Groups into one icon button and give the text field its own row.
- **Options:** A) drawer plus collapsible sidebar below 960px (recommended, L, passes 1.4.4 and 1.4.10 at 200%). B) Peek always an overlay as Linear does (L). C) Peek 320px under 1100px (M). D) horizontal scroll only (S, still fails 1.4.10). E) raise `minWidth` and clamp zoom (S, breaks the chosen zoom).
- **Linear comparison:** `28-issue-peek.png` (417px floating card over the list, not a column) and README "Sidebar 244px wide".

### UX6 Status Glyphs

- **Sources:** V7, A4
- **Severity:** Medium. **Size:** S.
- **Screen:** Tree rows, Peek and page Status, status pickers.
- **Screenshots:** [08-tree-done-loaded.png](2026-10-10-ux-review/08-tree-done-loaded.png), [08-tree-done-loaded-light.png](2026-10-10-ux-review/08-tree-done-loaded-light.png), [05-tree-keyboard-focus-light.png](2026-10-10-ux-review/05-tree-keyboard-focus-light.png), [32-picker-status.png](2026-10-10-ux-review/32-picker-status.png)
- **Evidence:** `StatusDot.tsx:14-23` (fill none only for new; In Progress and Done both fill), `styles.css:21-22`. PSAPAC-13 (yellow disc) and PSAPAC-22 (green disc) look alike apart from hue.
- **Problem:** To Do is a ring, but In Progress and Done are solid circles that differ only by amber versus green. Light amber measures 2.82:1 on canvas and 2.36:1 on the selected row (dark 9.25).
- **Why it matters:** Red-green colour deficiency confuses amber and green. The accessible name carries status for screen readers; the gap is for sighted users.
- **WCAG 2.2:** 1.4.1 Use of Color, 1.4.11 Non-text Contrast (3:1 needed, measured 2.82 and 2.36).
- **Recommendation:** One shape per category at 14px with a 1.5px stroke: To Do an empty ring (as now), In Progress a ring with the right half filled, Done a solid circle with a `var(--canvas)` check cut-out (as `TypeIcon.tsx:38` does for Task). Darken light `--status-doing` to `oklch(0.58 0.15 75)` (4.19:1 on canvas).
- **Linear comparison:** `15-picker-status.png`, `02-my-issues.png`, `14-issue-comments.png`: distinct glyphs (dashed circle, half circle, check). README names the green Done icon as the accent.

### UX8 Letter Shortcut Scope

- **Sources:** A6
- **Severity:** Medium. **Size:** S.
- **Screen:** Every screen with a Tree, Peek or page.
- **Screenshots:** None; behaviour finding from source and key probes.
- **Evidence:** `keymap.ts:64-72` (letter table), `:81-90` (`resolveKey`), `:41` (exclusions), `Shell.tsx:479` (one document `keydown` listener); `docs/reference/shortcuts.md` lists the keys as global.
- **Problem:** `T` on a sidebar button or toolbar control starts or stops the timer, which writes a worklog. `C S A L P` open dialogs and pickers. Only text fields, pickers, dialogs and editors are excluded, and no setting turns the keys off.
- **Why it matters:** Speech-input and switch users trigger these by accident.
- **WCAG 2.2:** 2.1.4 Character Key Shortcuts (Level A).
- **Recommendation:** Act on a letter only when focus is inside the Tree, Peek or issue page: `event.target.closest('[role=tree], aside[aria-label=Peek], section[aria-label="Issue page"]')`. Cmd chords stay global.
- **Options:** A) scope to Tree, Peek and page focus (recommended, S, no public-contract change). B) A "Letter shortcuts" switch in the sidebar footer (M, changes the settings file shape, so Ask First). C) both.
- **Linear comparison:** n/a (behaviour). Linear scopes letter keys to list and issue views.

### UX12 Focus and Selection

- **Sources:** V8, A5
- **Severity:** Medium. **Size:** M.
- **Screen:** Tree rows and group headers, sidebar active view, Theme toggle.
- **Screenshots:** [05-tree-keyboard-focus.png](2026-10-10-ux-review/05-tree-keyboard-focus.png), [22-peek.png](2026-10-10-ux-review/22-peek.png), [22-peek-light.png](2026-10-10-ux-review/22-peek-light.png), [17-sidebar-views-list-light.png](2026-10-10-ux-review/17-sidebar-views-list-light.png), [60-edit-refused-light.png](2026-10-10-ux-review/60-edit-refused-light.png)

- **Problem:** Focus is a square 2px accent frame at full bleed, the loudest thing on screen, and focused and selected rows look the same. Draw the accent ring only on the Tree container. Theme toggle: weight 500 and a 1px `--field-border` on the pressed segment.
- **Linear comparison:** `26-row-keyboard-focus.png`, `27-row-selected.png`; README Row focus about `#1a1a1b` and `#2c2e4a`, selected about `#242647` and `#373a66` (fill plus edge).

### UX14 Pending Edit State

- **Sources:** I2
- **Severity:** Medium. **Size:** M.
- **Screen:** Peek after a pick while the write is held.
- **Screenshots:** [55-edit-pending.png](2026-10-10-ux-review/55-edit-pending.png), [57-undo-pending.png](2026-10-10-ux-review/57-undo-pending.png)

## Proposed Stories
