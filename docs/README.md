# Documentation

Docs follow [Diataxis](https://diataxis.fr/): each page is one kind (tutorial, how-to, reference or explanation), never a mix. `architecture/` is the explanation home.

| Folder | Kind | Holds |
|---|---|---|
| [Tutorials](tutorials/README.md) | Tutorial | Learning by doing: the first run of the CLI and an agent session |
| [How-to](how-to/README.md) | How-to | Task recipes: install, test and develop; add a command or a shortcut |
| [Reference](reference/README.md) | Reference | CLI commands, error codes, configuration, shortcuts |
| [Architecture](architecture/README.md) | Explanation | How the system fits together, and why |
| [ADRs](adr/README.md) | Decision | Architecture decision records, superseded rather than edited |
| [Design](design/README.md) | Design | Numbered design docs, written before a large feature is built |
| [Runbooks](runbooks/README.md) | How-to | Steps for token and Jira problems |
| [Standards](standards/README.md) | Reference | Rules for code, git, testing, review and docs |
| [Security](security/README.md) | Explanation | Threat model for the API token and the Jira connection |
| [Product](product/README.md) | Reference | The roadmap, requirements and acceptance criteria |
| [Discovery](discovery/README.md) | Record | Research, spikes and question rounds |
| [Templates](templates/README.md) | | Starting points for new documents |

New here? Read [ARCHITECTURE.md](../ARCHITECTURE.md), [CONTEXT.md](../CONTEXT.md) for domain terms, then the [standards](standards/README.md).

[Documentation](standards/documentation.md) sets where each kind of document goes, who owns it and how to write it.
