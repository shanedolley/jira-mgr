## Traps

The function, file and script names in each trap were checked against the code at main 0644a3b on 2026-10-16 (#247 changed package files only) (`git grep` at origin/main), except `expectStarted` (a suggestion, not code). An accepted limit or a live-Jira fact carries its own date.

- **A Tree level default changes the rows every e2e sees at launch** (#209, 2026-10-13). A fresh launch opens at Stories, so Subtasks and Done chips start hidden. A suite that needs Subtasks calls `showEverything` from `e2e/desktop/harness.ts`.
- **Linux CI differs from macOS** (met on #159, #163 and #190; one red CI round each). Now in [AGENTS.md](AGENTS.md).
- **A release before the write is held is lost** (met after PR #170, fixed by PR #171). The e2e fake's `releaseEdit` is `held.shift()?.()` in `apps/desktop/src/main/e2e-fake.ts`, so releasing before the write is held does nothing and the dialog waits forever. Wait for the write (`settle(n)` or `expect.poll(writes)`) before `releaseEdit`.
- **An edit's read-back must skip while a newer edit of the issue is in flight.** A read that lands late overwrites the newer edit on screen. Any new read-back of an issue uses `applyUnaskedRead` (`optimistic.ts`; fixed by #114).
- **Reproduce CI-only races with CPU throttling.** `throttle()` in `e2e/desktop/keyboard.test.ts`, `bulk.test.ts`, `manual.test.ts`, `page.test.ts`, `palette.test.ts`, `timetracking.test.ts` and `toast.test.ts` sets CDP `Emulation.setCPUThrottlingRate` to 20. Never read derived rows in an event handler right after a state change (#159: Tree rows built from `useDeferredValue(filters)` read a render late).
- **Wait out ProseMirror's focus timer before a caret key in e2e.** `focusSettled()` in `e2e/desktop/editor.test.ts` does it (#103).
- **Single-file e2e runs test stale code.** `npx playwright test desktop/<file>` inside `e2e/` runs the last build in `apps/desktop/out`. Run `pnpm build` first; `pnpm e2e` builds first.
- **Parallel e2e runs starve Electron.** Several worktrees at once make 5 to 25 tests time out in `beforeEach`. Use `--workers=1` and the shared `lockf` lock, and rerun on a quiet machine before treating a `beforeEach` timeout as real. Met again 2026-10-12: a builder without the lock lost two full runs (SIGTERM, exit 137) while another agent held it; name the lock path in every dispatch that runs e2e.
- **A killed `pnpm e2e` was restarted before anyone read the change** (2026-10-15, four kills). A builder whose `pnpm e2e` is killed restarts it unless the dispatch forbids it outright. Shane asked on 2026-10-15 that the full suite run once, after the batch is developed. Put the targeted command (`pnpm build`, then `cd e2e && lockf <lock> npx playwright test desktop/<file>.test.ts --workers=1`) in the first dispatch and forbid `pnpm e2e` in it. The lock path is the shared one named under `/clear` below.
- **Read the failing test's name and assertion before rerunning.** A rerun that passes can hide a real bug (a date committed twice failed 15 of 40 runs before its fix; the caret bug was another).
- **Hover colour flakes** (resolved 2026-10-13 by #211): CI lost a hover between `hover()` and the colour poll, and the cause stays unknown. `hoveredColourOf` in `e2e/desktop/buttons.test.ts` hovers on every poll try; use it, or hover inside the poll, for any new hover assertion.
- **Unanchored row-label locators match Epic progress** (met 2026-10-12 on PR #193, one red CI round). Since #150 an Epic row's label ends "N of M done", so `item(/2 done/)` also matched two Epics and passed only when its poll landed before the Done phase loaded (7 of 8 local runs failed). Match a row label exactly or anchor it (`/^2 done$/`).
- **The Electron dist is missing after every `pnpm install`** (Electron 44 has no install script and downloads on first `require`, with no lock; two workers racing that download gave CI `spawn ETXTBSY`, fixed by #211). The check and the fix, `pnpm --filter @jira-mgr/e2e exec install-electron`, are in [AGENTS.md](AGENTS.md).
- **Parallel e2e workers share a clipboard** (met 2026-10-13, one red CI round on PR #214). On Linux each worker now starts its own Xvfb, which gives it its own X clipboard. On macOS the pasteboard stays global, so the copy tests that read the system clipboard (`actions.test.ts` and `palette.test.ts`, through `clipboardText`) can flake with more than one worker: run e2e with `--workers=1` locally.
- **`gh run list --commit` needs the full SHA** (2026-10-14). A short SHA returns nothing, so a wait loop on it never ends. Use `--branch <branch>` or `$(git rev-parse <sha>)`. Now in [AGENTS.md](AGENTS.md) and the git workflow standard.
- **Prettier realigns a whole Markdown table** when one row grows, so two branches that each add a row to `apps/desktop/README.md`'s file table conflict on every row (met 2026-10-14 rebasing #210 onto #213). #226, #227, #229, #231, #232, #233, #239 and #240 to #245 each changed it or may have, and are merged. Resolve by collapsing table padding on the base, ours and theirs (`perl -pe 'if (/^\|/) { s/ {2,}/ /g; s/-{3,}/---/g }'`), running `git merge-file`, then `prettier --write`.
- **Starting colima starts Shane's own containers** (2026-10-13; a #211 builder did it twice for Linux probes). Ask before starting colima or docker, and prefer CI or a reasoned argument for Linux-only evidence.
