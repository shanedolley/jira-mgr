# End-to-End Tests

Playwright tests that cross package boundaries. Unit and integration tests sit beside the code they test.

| Suite      | Drives                                                                                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `desktop/` | The built desktop app, through Playwright's Electron driver, on a fake Jira and a fake Keychain: `shell.test.ts`, `tree.test.ts`, `page.test.ts`, `create.test.ts`, `delete.test.ts`, `keyboard.test.ts`, `editor.test.ts`, `avatars.test.ts` |

## Run

```
pnpm e2e
```

The command builds the desktop app, then launches `apps/desktop/out/main/e2e.js`, an entry that runs the real app with `fetch` replaced by an in-memory Jira (`src/main/e2e-fake.ts`) and the Keychain replaced by core's own code over a fake `security`. It refuses to start without `JM_STATE_DIR`, and each test gives it a temporary folder, which also holds Electron's own storage. Nothing reaches the network, the real Keychain or the real state folder. The fake holds every write (an edit, a transition or a sprint move) until a test calls `releaseEdit`, so a test sees the optimistic state without a timing window. It answers what the issue page asks: a read of one issue, transitions, assignable users, a board with sprints, and create metadata with Customer, Engagement and priority options. It applies edits as the live project does, so an estimate edit also moves the remaining estimate and Time remaining, and it refuses the summary `reject me` and the priority `Highest`, so a test can watch a rollback. `counts.issueReads` lists each read of one issue and `counts.editBodies` each write received, so a test checks what was sent and that an edit reloaded no list. It creates and deletes issues too. A create holds until `releaseEdit`, answers with the next number from 2000 (clear of `JM_E2E_BULK`'s 1000 to 1999), and applies the PSAPAC automation's rewrite as the handover Traps describe it: every new issue gets the label `PSAPAC` and a 4h original estimate with nothing remaining, and a new Task is also moved to the internal Customer, under `PSAPAC-50`, in Sprint 5, whatever the request asked. It refuses the summary `reject me`, a Subtask with no parent, and a missing Customer or Engagement. A delete holds the same way, refuses an issue with subtasks unless `deleteSubtasks=true`, removes the subtasks with it, leaves the other children of the issue without a parent, and answers 403 for `PSAPAC-3`, so a test can watch a delete roll back. `dropIssue` (in `harness.ts`) removes an issue as if someone else deleted it, so the next refetch loses it. `counts.editBodies` holds a create's request body and, for a delete, `{ delete, deleteSubtasks }`. It also holds the first Done search page until `releaseDone`, so a test sees the Tree before Done issues arrive, and `failDone` makes the next Done page answer 500. `failRead` makes the next read of one issue answer 500. `moveIssue` (in `harness.ts`) changes an issue's status as if someone else did, with no hold and no count, so the next window focus reads it. `counts.doneEarly` counts Done pages requested before the unresolved phase served its last page, which must stay 0. `JM_E2E_BULK=<n>` adds that many open Stories under one Epic, for the virtual window test. `desktop/harness.ts` launches the app and holds these helpers. Windows open invisible, click-through and without focus, so a run never flashes on your screen, catches your clicks or types into whatever app you are using. (macOS keeps part of every window on a display, so the window cannot sit off-screen.) On Linux without a display, run `xvfb-run --auto-servernum pnpm e2e`. When `CI` is set, the test passes `--no-sandbox` to Electron, because GitHub's runners lack the setuid sandbox helper.

Electron downloads its binary on first launch.

The CLI will get a `cli/` suite that runs the built `jm` binary as a subprocess and checks `--json` output and exit codes.

`desktop/views.test.ts` covers the sidebar's saved views. It reads `views.json` and `settings.json` in the temporary `JM_STATE_DIR`, the files `jm view list` and the app share, to check what the app wrote, and writes `views.json` itself to check what the app reads.

`desktop/lateRead.test.ts` covers the create toast's second read: it names what the automation changed after the create returned, and shows no second toast when the read finds nothing new.

`desktop/keyboard.test.ts` covers D7: the `Cmd+K` palette, the letter shortcuts on the Tree and the page, the `Esc` order, and `Cmd+Z` with its toast, its stale check and its native-undo carve-out. It presses real keys, so the guards (text fields, dialogs, modifiers) are tested where they run. `Meta+z` and `Meta+k` work on Linux too, since the keymap accepts Ctrl or Cmd.

`desktop/editor.test.ts` covers D4 in groups: typing with markdown shortcuts and saving with `Cmd+Enter`; read-only blocks saving unchanged; conflict, refusal and re-read handling; image drops, uploads, undo of an upload, cut and paste of an upload, existing images; links; `Esc` and the discard dialog; drafts, logout and the quit prompt; pasted HTML; `Cmd+Z` after a save; the page-wide file drag with its drop zone, a non-image refused, and a page falling back to the Tree when its issue was deleted (`dropIssue` plus a window focus). It runs the TipTap description editor on PSAPAC-1, whose fake description holds a panel, a table, a mention, a linked code span and an image, and on PSAPAC-4, which has none. It drives real keys and a dropped `File`, and checks the ADF each write carried. The fake also answers attachments: `GET /rest/api/3/issue/{key}?fields=attachment` (not counted as an issue read), `GET /rest/api/3/attachment/meta`, `POST /rest/api/3/issue/{key}/attachments` (held until `releaseUpload`, recorded in `counts.uploads`), and `GET /rest/api/3/attachment/content/{id}`, which redirects to the media service with the file id in the path or, with `redirect=false`, returns a small PNG. `failUpload` makes the next upload answer 500 at once, `setDescription(key, adf)` changes a description as another user would (for the conflict tests), and `normaliseDescriptions` makes every saved description come back with a `localId` on each paragraph, as Jira may. `counts.openExternal` lists the links the app opened and `counts.quitPrompts` counts quit prompts; the e2e entry passes stand-ins for `shell.openExternal` and the native quit dialog. Playwright answers a real `beforeunload` dialog itself, so the quit test raises `will-prevent-unload` from main and checks that the renderer blocks unloads only while a draft exists. Drag and drop is dispatched as `DragEvent`s carrying a `DataTransfer` with a `File`, on `body` for `dragenter` and `dragleave` and on the `[data-drop-zone]` element for `drop`. A click with no pause between press and release can go unseen by ProseMirror, so the tests that move the caret with the mouse click with `delay: 60`.

`desktop/avatars.test.ts` covers D13. The fake gives Test User an image, served from `avatars.fake.atl-paas.net` (a host main allows, with no network), gives Other User an image that answers 404, and gives Cy Young none. `counts.avatarFetches` lists each avatar request and whether it carried credentials, which none may.

`desktop/package.test.ts` launches the packaged `apps/desktop/dist/jira-mgr.app` on a scratch `JM_STATE_DIR` and expects the login screen. It skips unless `pnpm package` has built the app, so CI (Linux) skips it and the Mac check is `pnpm package && pnpm e2e`.
